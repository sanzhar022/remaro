# REMARO — PRODUCT IMPORT PREPARATION

Команда по умолчанию выполняет только dry-run:

```powershell
npm run products:import
npm run products:import -- --file "C:\Users\yerty\Downloads\Remaro_товары 0 (восстановлен).xlsx"
```

Требуются Node.js, зависимости проекта, Python 3 с openpyxl (проверено с 3.1.5) и DATABASE_URL из .env.
При необходимости задайте PYTHON — путь к интерпретатору.
Поддерживаются --sheet (по умолчанию «Товары») и --report-dir (reports/product-import).
Читатель не исполняет формулы, макросы или инструкции из ячеек. Формулы блокируют строку.
Другие листы перечислены в отчёте, но не считаются товарами. Полностью пустые строки пропускаются, номера Excel сохраняются.

## Отчёты

- reports/product-import/dry-run.json: все исходные значения, ошибки, предложения SKU/slug, характеристики, ссылки на фото, совпадения с БД и диагностические названия.
- reports/product-import/summary.md: сводка и все номера сдвинутых строк.
- reports/product-import/categories.md: каждая пара Excel, количество строк, существующие DB name/slug/id и статус.

Счётчики ошибок показывают число затронутых строк, а не число уникальных ключей; они могут пересекаться.
BLOCKED в сводке исключает демо. EXISTING PRODUCTS включает совпадения у демо и заблокированных строк.
CATEGORY MATCHED / NOT FOUND / AMBIGUOUS считают пары категорий; построчные результаты находятся в JSON.
WITH STOCK означает корректный числовой остаток, включая ноль.
Сравнение UPDATE_CANDIDATE охватывает основные поля Product; это диагностика, обновления не реализованы.
Изображения сохраняются только как источники в JSON. ProductImage не создаются: существующий интерфейс показывает placeholder.
Рейтинг и признаки популярности/хита валидируются. Отсутствующие значения используют дефолты модели.
Необязательная некорректная oldPrice исключается из предложения с предупреждением.

## Политика безопасности

Чтение БД выполняется через PostgreSQL BEGIN ISOLATION LEVEL REPEATABLE READ READ ONLY и завершается ROLLBACK.
Нет seed, синхронизации категорий, миграций, db push, UPDATE или DELETE.
Категории сопоставляются по точному нормализованному имени внутри соответствующего родителя/предка.
Префиксы «10.3» и различия ё/е нормализуются. Совпадения вне ветки являются предложениями в JSON, а не автоматическим mapping.
Новые категории и изменения parentId не выполняются.

Цена/остаток должны соответствовать PostgreSQL Int: целые неотрицательные до 2147483647.
Дробная цена не округляется. Отсутствующий stock блокируется. Предложение stock=0 требует отдельного решения пользователя.
Отсутствующий SKU получает стабильное предложение по SHA256 категории, подкатегории, бренда и названия; оно не подставляется.
Изменённые/пустые slug также требуют исправления источника. Проверяются дубликаты исходных и предложенных slug.
Сдвиги колонок не исправляются автоматически. Демо исключаются всегда в рамках этого этапа.

## Будущий apply — только после отдельного разрешения

На этапе подготовки НЕ запускать --apply.

Код создания дополнительно требует --review-sha256 из согласованного dry-run.
Токен связывает файл, снимок БД и результат анализа. Любое изменение требует нового dry-run и согласования.
При любой заблокированной недемонстрационной строке весь apply отклоняется.
Создаются только CREATE, существующие товары никогда не обновляются.
Создание выполняется атомарно в Serializable-транзакции с повторной проверкой SKU, slug и категории.
Уникальные ограничения защищают от параллельных конфликтов; повторный запуск не создаёт дубли.
Отчёт dry-run описывает состояние до применения; будущий результат применения записывается отдельно в apply-result.json.
Загрузка изображений не выполняется.
